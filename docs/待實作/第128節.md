## 128. 每日自動備份與自己還原（2026-11-21；起因：18f～18m 讀檔時把基因壓平的錯，沒有備份可以救）

狀態：可以實作，**優先做，排在第 126、127 節之前**。順序：128.1 先回報 → 128.2 → 128.3 → 128.4 檢查。照 CLAUDE.md 0.2.7：不自行 commit、push；全部做完存檔，BUILD 只升一次。回報的內容和本節的假設不同時，**先停下來問**。

背景：遊戲平常不寫備份，只有舊格式轉換、修復壞資料、玩家按「保留舊存檔」時才寫。程式出錯把存檔改壞時，沒有前一天的版本可以回去。

### 128.1 先回報（不改程式）
1. 現有 `backupSaveStrict` 怎麼寫（文件名稱、欄位、超過大小怎麼分段）、`recover98` 怎麼讀。
2. 主控台現在的規則（`tools/firestore_rules_console_117.txt`）對 `backups` 是「不能刪除、可以改自己的」；照 128.2 的做法夠不夠用，要不要改規則。
3. 一份存檔平均多大；每人 7 份會佔多少。

### 128.2 每日自動備份
- **什麼時候寫**：每天（手機本地日期，沿用 `dayKey`）第一次成功讀到雲端存檔之後、**在 `migrate` 和 `repairState` 改動任何東西之前**，把剛讀到的原始存檔原樣備份一份。這樣當天的新版程式就算把存檔改壞，備份裡是改之前的樣子。
- **留幾份**：最近 **7 天**，用固定的 7 個位置輪流覆寫（文件名稱用「uid＋星期幾」這一類固定的名字，因為規則不允許刪除）。每份記下日期、時間、當時的 BUILD、存檔大小。
- 備份失敗（網路、超過大小）不影響進入遊戲，只在下次登入再試；連續 3 天失敗時在設定頁顯示一行小字「備份沒有成功」。
- 新玩家第一天沒有東西可備份，略過。
- 現有的其他備份（修復、舊格式、保留舊存檔）照舊，不算在這 7 份裡。

### 128.3 自己還原
- 入口：設定（或個人頁）最下面一行小字「從備份還原」。
- 列出手上有的每日備份：日期、時間、版本；點一份先顯示摘要（等級、金幣、種子袋幾包、田裡幾株），讓玩家確認是不是要的那一份。
- 還原要按兩次確認，文字：「現在的進度會換成這一份備份的樣子。確定嗎？」
- 還原之前，**先把現在的存檔另外備份成一份「還原前」**（固定一個位置，覆寫），還原錯了可以再還原回來。
- 還原後照正常流程跑 `migrate`、`repairState`，再存檔、重新載入畫面。
- 備份的 BUILD 比現在的程式新（理論上不會發生）就不給還原。
