19. 標本機制與服裝（2026-11-14 使用者確定方向；**第一階段已在 14i 實作**，見 19.0）
19.0 第一階段實作內容（14i）
- 範圍：採收標本、全服名額、命名、收藏櫃、品種權轉換。布料／服裝（19.3）尚未做。
- 名額常數 `SPEC_CAP=[0,0,5,3,2,1]`（依 `TIERS` 索引：稀有 5、史詩 3、傳說 2、神話 1；普通、少見 0＝不能做）。名額一律以常數為準，文件裡不存名額，改常數就生效。
- 採收條件 `specBlock(p,ph)`：成熟、未絕版、`ph.tier >= SPEC_MIN_TIER(2)`、`ph.stab >= SPEC_STAB(0.9995)`（和種子袋「成品」同標準）、自己沒有這個品種。採收不影響植株，之後照常收成。不收費。
- 資料：沿用既有集合 `rights`，文件 id = `rid(作物,外觀)`（和舊品種權同一份文件）。欄位 `{v:5, kind:'spec', crop, app, tier, g(基因型 JSON 字串), holders:{uid:{name,at}}, n, name, namerUid, namerName, auto(自動名稱), createdAt}`，寫入一律 `set(…,{merge:true})`，舊品種權的其他欄位（payouts 等）會留著。`specNorm()` 會把還沒轉換的舊品種權（public，或 pending 且未過期）視為「原擁有者持有 1 個、名字與命名者沿用」，所以別人先採收也會把原擁有者算進名額。
- 領取：`claimSpec(i)` 用 `db.runTransaction`，在交易內 `specClaimStep()` 檢查每人限一（`mine`）與名額（`full`）。命名：`nameSpec(id,v)`，只有 `namerUid` 本人、尚未命名時可命名（2–8 字，`nameTaken` 檢查圖鑑重名），成功後另外 `registry.add` 讓它進「品種圖鑑」與紀錄榜。已在 `registry` 有名字的外觀，第一個採收的人沿用原品種名與命名者，不能改名。
- 讀取：拿掉了監聽整個 `rights` 集合的 `onSnapshot`。需要名額時用 `specGet(id)` 只讀那一份文件（快取 60 秒）。舊品種權轉手收入改成登入時查一次 `where('payouts.<uid>','>',0)`。
- 玩家存檔：`state.specs=[{id,crop,key,tier,at,auto,from}]`（收藏櫃的清單）；舊版 `state.specimens`（已移除的舊標本）在 `migrate` 直接刪除。
- 一次性遷移 `specMigrate()`（登入後執行，旗標 `state.specV=1`，`newGame` 同步給旗標）：查 `rights where ownerUid==自己`（持有中的）＋ `regList` 中自己命名的品種 → 每個在交易中把自己加進 holders、保留名字與命名者 → 放進 `state.specs`。全部成功才設旗標，網路失敗下次登入再試；已在 `state.specs` 的不重複加。原擁有者一定保留，可能讓少數品種略超過名額。
- 介面：植株資訊的品種權區塊改為「果實標本」（`specBoxHTML`，顯示「全服 n／名額」，名額滿或已有時只顯示原因）；收成總表那一列改「採收標本」按鈕，可採收卻沒採收就按確定收成時提醒一次；圖鑑「品種權」分頁改成「收藏櫃」（`cabHTML`），列出圖示、名字（別人命名的加「命名者：某某」）、稀有度、取得日期、全服名額，第一個取得者在這裡命名；拜訪朋友時收藏櫃上方多一區「○○ 的收藏櫃」（唯讀，資料來自朋友存檔的 `specs`）。
- 已移除：品種權申請／命名公開／買賣的介面（`applyRight`、`rightPublish` 等函式仍在但沒有入口）、舊標本上架與鑑定（`kpick`／`ksave`、`appraise`、`specCard`、`rightsHTML`）。
- 安全規則：其他玩家要能寫入別人建立的 `rights` 文件（加入 holders）。舊的品種權買賣本來就需要這個權限，如果現行規則允許任何登入者讀寫 `rights`，就不用改；否則要加入 `match /rights/{id} { allow read, create, update: if request.auth != null; }`。
19.1 目的
取代現行「品種權」的獨佔登錄，給玩家清楚的目標：想做出某個樣子 → 選拔到成品 → 拿到標本 → 放進收藏櫃 → 解鎖布料做衣服穿給朋友看。
解決三個問題：作物做出來之後沒有用途、品種登錄太容易且規則越補越複雜、玩家缺少方向。
19.2 規則（已確定；**部分已由第 28 節取代**：所有稀有度都能做標本、名額與命名權只限史詩以上，見 28.3）（「標本不能交易」已由第 95 節修改：傳說以上、沒用過的標本可以交易）
取得條件：種子包達到「成品」（`lotCat` 判定，種下去全部長一樣）後，從該成品種出的成熟植株可以採收「果實標本」。不用世代數判定。
只有稀有以上可以做標本（普通、少見不行）。
品種 = 完整外觀（`appKey`）。名字只顯示在一模一樣的外觀上。
全服名額依稀有度（範例值，正式數字待定；測試期人少，名額先設小，例如稀有 5、神話 1）：
稀有度	全服名額（範例）
稀有	20
史詩	10
傳說	5
神話	3
每人每個品種只能有一個標本。名額滿了之後，其他人仍然可以種、可以賣果實和種子，但拿不到標本。
第一個取得標本的人為品種命名，其他人的標本顯示「名字（命名者：某某）」。保留搞怪命名的樂趣。
標本是永久道具、固定不變，不會因為之後種出更完美的而自動取代。完美度只留給紀錄榜。
標本不能交易（代表親手培育，像獎盃）。成品種子、用標本製作的衣服可以交易。
收藏櫃：個人收藏所有標本，朋友可以來看（展示、分享）。
名額領取必須用 Firestore transaction，避免同時搶最後一個名額時超額。資料讀取要分頁，不可一次監聽整個集合。
19.3 標本的用途：布料、染料、徽章（已確定）
標本不會被消耗，用途是解鎖。
標本解鎖三種東西：
布料底色：來自果皮顏色（例：星空色外套、黑曜色大衣）；
布料圖案：來自花紋（例：金色斑點圍巾、條紋帽 T）；
徽章、圖案：來自特殊造型或專屬造型（例：星星徽章、皇冠別針）。
衣服本身是一般好看的款式（外套、帽 T、圍巾、毛帽、貝雷帽、背包等），玩家把解鎖的布料、徽章套到任何款式上，由程式繪製顏色與花紋。
不要做成滿身蔬果造型（使用者明確表示會顯得幼稚或醜）。果實帽、果實小跟班這類可愛款只保留為其中一小類，選用。
穿著的衣服點開可看到「布料來自：某品種（命名者：某某）」。
稀有度越高，可做的款式越多、越特別（細節待定）；製作衣服要花金幣，作為回收金幣的管道。
19.4 尚未決定
各稀有度的正式名額、製作費用。
現有「品種權」資料如何轉換（例如每個已持有的品種權直接轉成標本並保留命名）。
收藏櫃的位置與呈現方式（獨立頁面、農場上的展示櫃、城鎮展示廣場）。
衣服款式清單；會和人物重畫（分層換裝、正側背三方向）一起設計，參考第 18 節畫風規範。
19.5 相關的已討論方向（未確定）
全服限量：每週限時珍稀植株、活動限定色全服只有固定數量。
回收金幣：市集成交手續費、製作費用。
賽季：每兩三個月一季，有主題、排行與限定獎勵。
不採用：真錢交易、加密貨幣、NFT、雙貨幣、強化失敗會損失的機制。
